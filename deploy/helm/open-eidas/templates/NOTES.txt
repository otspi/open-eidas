Open eIDAS a été déployé dans le namespace {{ .Release.Namespace }}.

L'amorçage complet (cérémonie de clé, première CRL, enrôlement puis
approbation de la TSU et du répondeur OCSP) prend quelques minutes.
Suivez sa progression :

  kubectl -n {{ .Release.Namespace }} get pods -w

{{ if .Values.ca.autoApprove.enabled -}}
Le conteneur "ca" journalise la cérémonie de clé et chaque émission ; le
conteneur "ra-autoapprove", chaque décision d'approbation :

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "open-eidas.fullname" . }}-ca -c ca -f
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "open-eidas.fullname" . }}-ca -c ra-autoapprove -f
{{- else -}}
L'approbation automatique est désactivée : la TSU et le répondeur OCSP
attendent qu'un opérateur nommé approuve leur demande d'enrôlement :

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "open-eidas.fullname" . }}-ca -c ca -- ca-server ra list PENDING
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "open-eidas.fullname" . }}-ca -c ca -- ca-server ra approve <transaction> "prenom.nom" "motif"
{{- end }}

Une fois {{ include "open-eidas.fullname" . }}-tsa prêt (Ready), exposez le
service et vérifiez l'horodatage :

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "open-eidas.fullname" . }}-tsa {{ .Values.tsa.service.port }}:{{ .Values.tsa.service.port }}

  DIGEST=$(sha256sum facture.pdf | cut -d' ' -f1)
  curl -s -X POST http://localhost:{{ .Values.tsa.service.port }}/api/v1/timestamp \
       -H 'Content-Type: application/json' \
       -d "{\"hash\":\"$DIGEST\"}"

{{- if .Values.tsa.gateway.enabled }}

La Gateway API expose également le service sur : https://{{ .Values.tsa.gateway.host }}
{{- end }}

Relire les journaux d'audit (chaînés par hachage, l'un et l'autre) :

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "open-eidas.fullname" . }}-tsa -- tsa-server verify-audit
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "open-eidas.fullname" . }}-ca -c ca -- ca-server verify-audit

Consulter la matrice de conformité ETSI telle que cette instance l'applique :

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "open-eidas.fullname" . }}-ca -c ca -- ca-server conformance

AVERTISSEMENT : comme le docker-compose de démonstration, ce déploiement
utilise une cérémonie de clé sans double contrôle, une approbation RA
automatisée sous un compte technique{{ if not .Values.ca.autoApprove.enabled }} (désactivée sur ce déploiement){{ end }} et SoftHSM en lieu d'un HSM
certifié. Voir docs/CONFORMITE-ETSI.md pour l'état exigence par exigence.
